# Refreshing human-unreviewed pages with OCR v2

## Completed batch — 2026-09-10

All 439 eligible pages were refreshed. Of 41,169 body lines, 41,057 received
new recognition; 40,944 outputs were accepted, and 225 lines retained their
previous readings (112 excluded during association/cropping, plus 113 withheld
after recognition). Text or typeface runs changed on 32,613 lines; this count
is not a claim that every change is a correction.

The [complete application registry](../pilot/human-review/ocr-refresh-v2.json)
lists every retained line and reason. The
[verification summary](../pilot/human-review/ocr-refresh-v2-summary.json)
confirms complete coverage, exact OCR-to-applied-text/typeface correspondence,
and unchanged protected pages, retained lines, furniture, stable IDs and UI
geometry. All 229 compact canonical records validate; the site builds all
651 leaves with regenerated reading hints. New text still needs general-AI
review followed by human review.

Original versions are preserved in Git at `14d7d617` and in the local backup
directory below. The excluded trial pages and f643 remain unchanged.

The production command is `scripts/refresh_unreviewed_ocr.py`. It uses the
packaged `nippo-calamari-v2-styled` model and its matching full-extent,
paper-white, rectified 48-pixel line preprocessing. It does not use the old
word-based typeface classifier or normalize diplomatic characters afterward.

## Protection and scope

Eligibility comes from correction history, touched human-review units and
explicit `human_checked` status, not a fixed numeric cutoff. At this run the
Issue history protects every page f13–f200. The frozen early trial references
also protect f248–f250, whose conversational human corrections predate the
Issue registry. f643 is excluded because it has no preserved OCR layout.

The inventory contains 439 eligible pages: f201–f247 and f251–f642. It covers
both structured Level 1 files and materialized scan-bootstrap candidates.
Non-body furniture, headings, stable IDs, indentation and browser crop
coordinates are retained. This is a body-recognition refresh, not a fresh
structural segmentation or all-line visual geometry review. Existing
quarantines (including the unusual f376 transition) are not promoted.

## Safe stages

1. `plan` records eligibility, the original Git commit, source/Markdown hashes
   and the model manifest hash. It copies every eligible original file and its
   geometry into `.cache/ocr-model/page-refresh-v2/backup` and `geometry`.
   Original committed data also remain recoverable from the recorded Git commit.
2. `prepare` matches saved OCR detections to existing body IDs using nearby
   position and relaxed old text only for identity. No reference text is passed
   to the recognizer. Duplicate, ambiguous, poorly matching, too-narrow and
   special displaced/decorated rows are retained rather than forced.
3. `predict` recognizes matching native-scan polygon crops using the packaged
   model. Predictions already present are reused; a prediction lock prevents
   simultaneous runs from changing the input links. Other model/data versions
   require a fresh work directory. Package file hashes are checked on every run.
4. `propose` decodes ordinary Unicode plus Roman/italic runs. Empty or strongly
   disagreeing results are withheld. Preserved metadata is not inferred anew.
   Markdown text and visible typeface must round-trip; export must be stable.
5. `apply` rechecks human-review protection and source hashes, then copies
   validated proposals into their original locations. Per-page results are
   recorded in `pilot/human-review/ocr-refresh-v2.json`. Interrupted runs can
   resume without overwriting an independently modified source.

Every body line is accounted for as either recognized or retained with a
reason. A retained reading is **not certified correct**; it needs later review.
Old durable notes on recognized lines are kept with an explicit possibly-stale
prefix. Historical AI-review files remain available but no longer cause the UI
to label replacement text as AI checked. The page gets `visual_draft` status
and `calamari_v2_machine_provisional` origin. A subsequent real AI review may
promote its status through the normal workflow. Kana hints are regenerated by
the ordinary site builder from the new runs; they are not canonical data.

Bootstrap packages retain their old audit as historical evidence and carry a
recognition-refresh annotation. Structural classification is unchanged.

## Commands

From the repository root, first inspect the plan and pilot:

```sh
python3 scripts/refresh_unreviewed_ocr.py plan
arch -arm64 .cache/ocr-model/venv-kraken-arm64/bin/python \
  scripts/refresh_unreviewed_ocr.py prepare --pages 201 230 251 376
python3 scripts/refresh_unreviewed_ocr.py predict --pages 201 230 251 376
python3 scripts/refresh_unreviewed_ocr.py propose --pages 201 230 251 376
```

After inspecting pilot crops, proposals and the UI, omit `--pages` to run the
whole inventory. Execute preparation before prediction, then proposal/application:

```sh
arch -arm64 .cache/ocr-model/venv-kraken-arm64/bin/python \
  scripts/refresh_unreviewed_ocr.py prepare
python3 scripts/refresh_unreviewed_ocr.py predict
python3 scripts/refresh_unreviewed_ocr.py propose
python3 scripts/refresh_unreviewed_ocr.py apply
python3 scripts/refresh_unreviewed_ocr.py verify
python3 scripts/compile_level1_markdown.py compile \
  pilot/format-v1-trial/level1-source pilot/format-v1-trial/level1 --check
python3 scripts/build_public_review.py
```

Commit and push validated data and code to publish the new baselines. Do not
publish the ignored native crops or model packages. Existing browser-local
edits use the normal baseline reconciliation; the refresh does not alter them.

`verify` checks the entire frozen inventory, including exact correspondence
between replacement text/typeface and the saved v2 predictions, unchanged
retained lines and geometry, and no changes to excluded pages. It writes
`pilot/human-review/ocr-refresh-v2-summary.json`. This audit concerns data
integrity and coverage, not the linguistic correctness of the OCR.

## Pilot inspection

The pilot used f201, f230, f251 and f376, including split sections and headings.
Twelve beginning/middle/end crop samples were visually inspected. Two tiny
incomplete crops (f201/c2-l048 and f376/c2-l039) yielded fragmentary readings;
the disagreement gate withheld both. f230 retained a decorated initial row
and an uncertain adjacent row. All stable body IDs and furniture were retained.
The local review interface showed Machine draft, the new text and refreshed
kana hints. The full compact-corpus validator and public-site build passed.
This is a pipeline sanity check, not an accuracy benchmark or an AI language
review of the generated pages.
